# Inam Ur Rehman Commission Shop — Backend API

A production-ready REST API for a distribution / inventory / sales / ledger
management system. Built with **FastAPI**, **SQLAlchemy 2 (async)**, **MySQL 8**,
**Alembic**, and **JWT auth**. Stock and ledger arithmetic is handled by
database triggers; the API validates input, writes rows in the correct order
inside a transaction, and returns the DB's post-trigger values.

The mobile app (built separately) consumes this API. Interactive docs:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

---

## 1. Tech stack

| Concern      | Choice                                             |
|--------------|----------------------------------------------------|
| Language     | Python 3.11+                                        |
| Framework    | FastAPI + Uvicorn                                   |
| ORM / driver | SQLAlchemy 2 (async) + `aiomysql`; `pymysql` (sync, for Alembic) |
| Migrations   | Alembic                                            |
| Validation   | Pydantic v2                                         |
| Auth         | JWT (access + refresh), bcrypt via passlib         |
| PDF          | reportlab                                          |
| Rate limit   | slowapi (on `/auth/login`)                          |

## 2. Prerequisites

- Python **3.11+**
- MySQL **8.x** running locally, with the target database created:
  ```sql
  CREATE DATABASE lasani CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  ```
- `mysqldump` and `mysql` client binaries on `PATH` (only needed for the
  backup/restore endpoints). Set `MYSQLDUMP_PATH` / `MYSQL_PATH` if they live
  elsewhere.

## 3. Setup

```bash
# 1. Virtualenv + dependencies
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Configure environment
cp .env.example .env
#   edit .env: set DB_PASSWORD, and a strong SECRET_KEY:
python -c "import secrets; print(secrets.token_urlsafe(64))"

# 3. Run migrations (creates tables, views, triggers, seeds the admin user)
alembic upgrade head
#   >>> the admin username/password is printed to the console here — copy it!

# 4. (optional) Seed demo data
python seed_demo_data.py

# 5. Run the server
uvicorn app.main:app --reload
```

One-liner (after `.env` is configured and the DB exists):

```bash
pip install -r requirements.txt && alembic upgrade head && python seed_demo_data.py && uvicorn app.main:app --reload
```

### First-login password

The initial admin password is randomly generated and **printed to the console**
during `alembic upgrade head`. Log in immediately and change it:

```
POST /api/v1/auth/change-password
{ "current_password": "<printed>", "new_password": "your-new-strong-password" }
```

## 4. Migrations

```bash
alembic upgrade head          # apply all migrations (initial = full schema)
alembic downgrade base        # drop everything
alembic revision -m "message" # create a new (autogenerated skeleton) migration
```

The initial migration reproduces the finalized MySQL schema exactly — every
table, generated column (`stock_value`, `outstanding_amount`, `payment_status`,
`total_amount`), index, view, and all triggers — then seeds the admin user.

---

## 5. Authentication & roles

Two roles (from the `users.role` enum):

- **admin** — full access to every module.
- **sales_entry** — restricted to: `GET /products`, `GET /customers`,
  `POST /sales-invoices`, `GET /sales-invoices/{id}` (own only), and
  `GET /sales-invoices?created_by=me`. Everything else returns **403**.

`is_active = 0` users are rejected at login and on every request (401).

Send the access token as `Authorization: Bearer <token>`.

## 6. Endpoints (all under `/api/v1`)

| Module | Endpoints |
|--------|-----------|
| Auth | `POST /auth/login`, `POST /auth/refresh`, `GET /auth/me`, `POST /auth/change-password` |
| Users (admin) | `GET/POST /users`, `GET/PATCH/DELETE /users/{id}` |
| Categories (admin) | `GET/POST /categories`, `PATCH/DELETE /categories/{id}` |
| Products | `GET /products`, `GET /products/{id}`, `GET /products/low-stock`, `POST/PATCH/DELETE /products` (admin), `GET /stock-ledger/{product_id}` (admin) |
| Customers | `GET /customers`, `GET /customers/{id}`, `POST/PATCH/DELETE` (admin), `GET /customers/{id}/ledger`, `GET /customer-ledger/{id}` |
| Suppliers (admin) | `GET/POST /suppliers`, `GET/PATCH/DELETE /suppliers/{id}`, `GET /supplier-ledger/{id}` |
| Purchases (admin) | `GET/POST /purchase-invoices`, `GET /purchase-invoices/{id}`, `GET /purchase-invoices/{id}/pdf` |
| Sales | `GET/POST /sales-invoices`, `GET /sales-invoices/{id}`, `GET /sales-invoices/{id}/pdf` |
| Payments (admin) | `GET/POST /customer-payments`, `GET/POST /supplier-payments` |
| Reports (admin) | `today-sales`, `monthly-sales`, `customer-wise-sales`, `product-wise-sales`, `outstanding-customers`, `stock`, `purchases`, `profit`, `cash-summary` (all under `/reports`, all support `?format=csv`) |
| Dashboard (admin) | `GET /dashboard/summary` |
| Backup (admin) | `POST /backup`, `GET /backup`, `GET /backup/{id}/download`, `POST /backup/{id}/restore` |
| Health | `GET /health` |

Consistent error shape across the API:

```json
{ "detail": "human readable message", "error_code": "STABLE_CODE" }
```

Paginated list endpoints accept `?page=` and `?page_size=` and return:

```json
{ "items": [ ... ], "total": 123, "page": 1, "page_size": 50 }
```

## 7. How stock & ledgers stay in sync

The API never duplicates trigger arithmetic. For a sale it:

1. Validates the customer, products, stock availability, and credit limit.
2. Computes `quantity_in_pieces`, `subtotal_amount`, and (for cash) `paid_amount`.
3. Inserts the invoice header (triggers bump `customers.current_balance` and
   write `customer_ledger` rows), then the line items (triggers decrement
   `products.current_stock` and write `stock_ledger` rows) — all in one
   transaction that rolls back fully on any error.
4. Re-reads the row and returns the DB's authoritative values.

## 8. Tests

Integration tests use `httpx.AsyncClient` against the running app and a live
MySQL database (run migrations first). They cover auth/roles and the core
purchase and sales flows.

```bash
alembic upgrade head
pytest
```

Test files:
- `tests/test_auth.py` — login, refresh, role enforcement
- `tests/test_purchase_flow.py` — purchase → stock + supplier balance + PDF
- `tests/test_sales_flow.py` — cash/credit sales, stock decrement, insufficient
  stock, credit-limit enforcement, customer payment
